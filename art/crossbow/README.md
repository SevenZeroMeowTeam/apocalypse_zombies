### 弦/缆运动学（无伸缩）
- 主弦半段长 `STRING_LEN = 4.000 u` **严格恒定**：`scale` 通道全程 `1.0`（自检逐帧核验，容差 0.005）。
- 弓臂每帧 = **绕枢轴的屈曲角**（0→±36°，选定曲线）× **沿臂轴的径向滑移**（解析解出，全程 ≤ 0.110 u），
  使「梢部—弦心」距离恰等于 `STRING_LEN`；弦两段内端逐帧汇于同一点（自检核验 ≤ 0.05 u）。
- 副缆长 `L_CABLE = 4.061 u` 亦恒定：导线滑座 z 由「缆长 = 梢到滑座距离」解出（静止 −6.60 → 拉满 −4.01），
  副缆内端逐帧咬住滑座（自检核验）。
- 拉满时弦心精确落在牙上 `(0.00, −4.20)`，凸轮自转 140°（左右镜像）。

> 为什么不是「纯旋转」模型：弓臂梢部到枢轴的半径固定时，弦心一旦离开静止位，两圆交点会经过相切退化点，
> 屈曲角会先暴涨再跳分支（上一版实测 0→86°→105° 跳变）。改为「屈曲角给定 + 沿臂轴滑移解析解」后，
> 过程连续、无分支翻转，弦长仍严格不变。

## 6. 已知偏差 / 不确定点（如实记录）

1. **静止姿态下左手与箭矢可见**：`hand_l`/`bolt_loaded` 的 rest 几何放在箭夹处与箭道槽内，仅靠动画 `scale=0` 隐藏，
   因此 Blockbench/Blender 的**静止预览**会看到「一支箭躺在箭道 + 一只握着箭的手套」；参考图本身无箭。
   这样做是因为硬约束禁止用缩放生成/隐藏部件以外的用法，而静止姿态无法用动画通道表达。
2. **总宽略小于参考比例**（9.11 u ≈ 57 cm）：为同时满足「长 ≤1.5 格」与弦长/弓臂屈曲有可行解，
   弓臂展收敛到 9.1 u（参考提示 60~65 cm）。
3. **副缆走向为「凸轮 → 导线滑座」的三角形**（参考图可能是交叉走线）：两缆各自从凸轮指向同一滑座，
   滑座由缆长恒定解出，行程约 2.6 u（16 cm）——真实复合弩副缆不会走这么远，属**风格化**取舍，
   以换取「缆长严格不伸缩 + 全程骨驱动」。
4. **弦/缆粗细 0.06/0.07 u（≈3.8/4.4 mm）**，略大于参考图的 2~3 mm：0.04 u 在 512 贴图下只有 2 px，
   游戏内几乎不可见，故小幅夸大（仍属「细弦」）。
5. **凸轮自转方向**按「弦自凸轮内侧放线」取的手性（左 +140°、右 −140°），未做真实凸轮槽的几何缠绕；
   凸轮以偏心椭圆 + 3 辐 + 弦槽凸榫 + 缆柱表达，保证自转肉眼可见。
6. 未接 Blender MCP：预览由本机 `D:/Blender/blender.exe` 无头渲染（脚本同样支持 `runpy.run_path` 写法）。
7. `art/crossbow/legacy_repeater/previews/` 内是**旧连弩**的预览图与 .blend，仅作留档，与 v2 无关。

## 7. 修复记录：左右凸轮/弓臂精确镜像（`1.1.26`）

用户报「模型不完整、错位」。取证结论：**同一个根因**。

`cam_wheel()` 用偏心椭圆 `r = CAM_R0 + CAM_DR*cos(a)` 建凸轮，`cos(a)` 在 a=0° 取极大 ⇒
**鼓包恒指向 +x**：右轮朝外（对）、**左轮朝内（错）**；4 根辐条、弦槽凸榫（−40°）、缆柱（140°）
也全按**绝对角度**摆放，`do_limb()` 左右各自独立算一遍 ⇒ 两侧是**平移副本**而非镜像，
两个凸轮是两个不同形状的轮子（同位置块尺寸 0.292 vs 0.096）。于是左轮的弦槽凸榫与副缆柱
指向枪身内侧，主弦/副缆看起来**接在不存在的东西上**、轮子像**缺了一块** ——
这正是「不完整 + 错位」。§5 本已写明凸轮应分左右手性（左 +140°/右 −140°），
说明手性一直是设计意图，只是几何从未做。

修法：生成器新增 `mirror_side(src, dst)`，在写出层之前把 `_r` 侧按 x=0 平面**精确镜像**成 `_l` 侧
（`origin.x → −(x+size)`、`pivot.x → −pivot.x`、`rot → (rx,−ry,−rz)`、归属骨改目标骨）。

| 指标 | 改前 | 改后 |
|---|---|---|
| 凸轮不成镜像的块 | 46 / 74 | **0** |
| 最大坐标差 | 0.14 u | 0 |
| 弓臂不成镜像的块 | 6 / 9 | **0** |
| 整机 x 包围盒 | −4.91 .. +5.04（中心偏 0.065u） | −5.045 .. +5.045（中心 **0.000**） |
| 总宽 | 9.11 u = 57.0 cm（§6.2 已知偏差） | **10.09 u = 63.1 cm** ✅ 落回参考的 60~65cm |

动画 json **逐字节未变**，体块仍是 501，骨骼仍是 21 —— 本次是纯几何修复，Java 零改动。
出货 `1.1.26`，md5 `308746e5faf92facab50275a855edb6c`；细节见 [`DELIVERY.md`](DELIVERY.md)。

顺带修掉一个工具缺陷：`tools/model_preview.py` 原先只按高度自适应取景，扁长物品
（本弩 14.9u × 4.87u）会被横向裁掉 —— 之前判读渲染图出错即源于此。现同时受高度与
XZ 外接半径约束，任何 yaw 都不出框。

### 追加：弓臂曲度、长度与「后掠」的实测边界（`1.1.27`）

用户要求「加长弓臂 + 加大后掠角，向参考图靠」。三条结论：

* **加长**：x 方向已顶到参考要求的 65cm 宽度上限，只剩 0.3u —— `LIMB_TIP_X` 4.42 → **4.55**
  （弓臂 +3%），外缘 |x| 4.50 → **4.63**；总宽 **64.7cm** 仍在带内。
* **加曲**：`LIMB_ARC` −0.30 → **−0.55**（弓臂前凸深 **1.12u → 1.30u**，+16%）。
  它只进几何、不参与弦/缆解算 ⇒ **零运动学风险**，是当前唯一能大幅改变弓臂观感的旋钮。
* **后掠：实测否决**（详见 [`DELIVERY.md`](DELIVERY.md) 1.1.27 节。**该结论已被 1.1.28 推翻** —— 真正的问题是
  解算器的建模假设而非几何，见下）。弦的半段长是从**弦心（牙）**
  量到梢部的常数，拉满时梢部必须沿臂轴滑移来维持它；滑移对「梢部相对 x 轴的夹角」极敏感，
  梢部后掠 **0.2u** 就把滑移从 0.28u 顶到 0.45u（阈值 0.35u）⇒ 视觉等同弓臂被拉伸。
  原设计梢部向前甩 −11.4° 恰是残差极小点，**动不得**。要真后掠，必须把弓片座/箭道/牙
  整套前段总成**刚性后移**（相对几何不变 ⇒ 滑移不变），但会撞上握把，需连后段一起重排。
* 顺带：拉程 3.10 → **3.20u**（`LATCH_Z` −4.20 → −4.10），滑移反而降到 **0.214u**（原 0.282u）。
  Java 侧 `PULL_TRAVEL` 1.85 → **1.95**、`CHANNEL` −4.65 → **−5.30** 已同步（两者都绑定 `LATCH_Z`）。

### 追加：解算器换成「双不变量」版 + 弓臂几何重定（`1.1.28`）

上一版判定「后掠必须把整套前段总成刚性后移」——**那个结论是错的**。真正的问题不在几何，在建模假设：
旧 `limb_pose` 是「先指定屈曲角 `FLEX_MAX` → 再解出臂长变化」，于是梢部一后掠、弦心后移，就必然
要求臂长被拉伸（实测 1.95u）。改成**「弦长恒定 + 臂长恒定」两圆交点定梢部、屈曲角当输出**后，
臂长成为常量、**滑移恒为 0**，后掠直接解锁 —— 弓片座/箭道/握把一个都不用动。

* 静止后掠角 **−11.00°（前甩）→ +6.34°（后掠）**（`LIMB_TIP_Z` −7.30 → −6.20）。这就是参考图里
  凸轮与弓片座基本同平面的样子；旧版把弓臂整个向前甩出去，所以才显得「短而直」。
* 牙 z −4.10 → **−3.30**（正好落在扳机 z −3.40 上，真弩的挂机位置），拉程 2.90u。
* 曲度 −0.55 → **−0.80**，剖面 `sin` → **`sin²`**（端部斜率为 0 ⇒ 去掉凸轮接合处约 25° 的折角），
  分段 7 → 9。实测**路径长 3.857 → 4.022u**、**中段前凸 0.550 → 0.800u（+45%）**。
* **臂轴滑移 0.214u → 0.000u**，拉满屈曲 **19.46°**（由几何解出，不再由常量指定）。
* Java：`PULL_TRAVEL` 1.95→**1.65**、`STRING.z` −6.05→**−4.95**、`CHANNEL.z` −5.30→**−4.50**。

## 8. 修复记录：cube 级 pivot 漏取反 → 游戏内散架（`1.1.59`）

用户报「模型散架：各部件位置不对、彼此分开」，且**所有场景**都这样（第一人称 / 物品栏 / 地上）。

**取证**：geo 数据本身看着是干净的 —— 21 根骨、515 个方块全部归到骨上、根节点上 0 个、
骨级 pivot 左右对称、`format_version` 与其它枪一致、`display` 与渲染器也没有多余变换。
但逐个方块比对 `origin.x` 与 `pivot.x` 的符号后就露馅了：

| | |
|---|---|
| 带 pivot 的方块 | 421 |
| **`origin.x` 与 `pivot.x` 反向** | **372**（`cam_l`/`cam_r` 各 74/74、`scope` 128/175、`cable_slide` 60/66、`limb_l/r` 各 11/13） |

也就是说：方块的 `origin` 已经镜像了，而它**绕以旋转的 pivot 还停在镜像前的那一侧** ——
每个方块绕一个在**身体另一侧**的支点转 8.85°~39°（`limb_l` 抽样），自然各奔东西。

**根因**：`tools/crossbow_v1.py` 的写出行 `game_convention_geo()` 取反了**骨级** pivot、
镜像了 cube 的 `origin`、取反了 cube 的 `rotation` —— **唯独漏了 cube 自己的 `pivot`**。
三样都做了，漏了第四样；注释里那句「立方体坐标 / 骨骼 pivot：X 取反」也没提这一档。

**修法**：`game_convention_geo()` 补一条 `cube['pivot'] = _neg_axes(cube['pivot'], _NEG_POS)`。
pivot 是一个**点**（不是最小角），所以按普通点镜像即可，与骨级 pivot 同一条规则 ——
不要套 `origin` 那条 `-(x+size)`。

**范围**：只有十字弩中招。它是唯一「既走本文件这套取反层、又带 cube 级 pivot」的模型；
awm 339 / s686 202 / uzi 128 / m1 218 / mosin 91 个带 pivot 的方块**全部正常**。

**验证**：修复后 421 个方块的支点**全部**落回自身包围盒 ±1.5u 内（修前只有 195）。
另外确认左右骨的 `rotation` 本来就是正确镜像的（`cam_l` 的 rot.y 全负 65 / `cam_r` 全正 65），
所以本次**只动了 pivot 一项**，没有连带改动 rotation。
