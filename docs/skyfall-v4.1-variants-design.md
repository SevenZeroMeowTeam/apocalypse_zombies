1. **每个技能的第二身份**：正式版六个技能除了主机制，还有各自的“后手/副产物”（子午线的线切割、
   七星的连线沟槽与星核、超立方的地块抬升、天球仪的副星撞击、冈格尼尔的针体残留）。
   我们 4.0.0 的六协议**主机制都齐了**，但都缺少这种“打完世界还在说话”的第二层。
2. **UX 的最后一公里**：径向技能菜单、每个技能独立键位、冷却环、尺寸危险确认、速度滑条。
   我们有终端 GUI 与广播/跳过，但**没有轮盘、没有危险确认、没有冷却环**。
3. **可回收的战场残骸**：参考包的钨针/星核能被挖回来，形成“打击 → 采集 → 合成”的闭环。
   我们的地形签名目前只留视觉，没有经济出口。

> 明确不做：34 个 GLSL shader、FBO 后期管线、Mixin 相机、多线程世界编辑引擎、
> 完整 64 格地块抬升（性能工程另立专项，不塞进本版）。

## 1. 核心决定：不新增第 7 个协议，做「协议改型 VARIANT」

**为什么不加第 7 个 `OrbitalStrikeMode`**：现在 `OrbitalStrikeMode`（6 个枚举）× `StrikeProtocol`
（6 份 XML）× 载体贴图 × 客户端电影 × HUD × 终端轮盘是一套 1:1 的闭环。加第 7 种会同时改动
枚举、XML 注册、贴图映射、电影分支、终端节点布局、协议号、配置默认值 —— 收益却只是“再多一根光柱”。

**VARIANT 的思路**：每个协议保留同一个 `mode`（复用现有电影/载体板/相位机），但允许**两种打法**；
变体只改「地形签名 + 服务端结算 + 客户端局部演出」，不动整套引擎。

### 1.1 数据模型

在现有 `strike/*.xml` 里追加 `<variants>`（缺省时视为只有 `default`，旧存档/旧资源包不受影响）：

```xml
<protocol id="dawn" mode="laser" display="黎明" codename="DAWN // 黎明" color="#FFF2C4">
  <phases> ... 不变 ... </phases>
  <terrain shape="purge"/>
  <variants default="focus">
    <variant id="focus"    display="聚焦"   codename="DAWN // 聚焦"/>
    <variant id="meridian" display="子午线" codename="MERIDIAN // 子午线"
             terrain="sweep" length="128" width="5" depth="14" speed="4"/>
  </variants>
</protocol>
```

- `StrikeVariants.load(protocol)`：JDK DocumentBuilder 解析，失败回落到内置定义（与现有
  `StrikeProtocols` 同一套容错策略）。
- 终端把「每个 mode 选中的 variant」写进 `SkyfallTerminalBlockEntity` 的 NBT（`Variant.<mode>`），
  旧终端读不到就用 `default`。
- 网络包 `OrbitalStrikePacket` 追加 `variant` 字符串（协议号升 `"3"`，同版本联机）。

### 1.2 终端 UI 改动（小）

协议轮盘节点下方加一行 `变体 ◀ 聚焦 ▶`，只对**有多个 variant 的协议**显示；切换走现有
`TerminalActionPacket` 的新 opcode（服务端校验 variant 是否属于该 protocol）。终端面板其余布局不动。

## 2. 三个改型（参考 → 我们的原创差异）

### 2.1 DAWN · 子午线 MERIDIAN（参考：Meridian 的线切割）

- **参考做法**：轨道镜阵把一条“子午线”烙过地表，一次成形、静态沟槽。
- **我们的原创**：不是瞬间成形，而是一道光束**从一端扫到另一端**：
  - 长度 96–256 可调，扫速 4 格/tick（约 2.5 s），**光束头是可见的、会移动**；
  - 头过之处留下 5 宽 × 14 深的玻璃化沟槽（坑壁白玻璃/海晶灯点），身后余烬；
  - 玩家能看着亮头过来、横向跑开 → 参考包没有的“动态躲避窗口”；
  - 只净化亡灵（沿用 DAWN 规则），玩家/村民/动物不受伤；
  - 两端各留一个圆形玻璃坑，中点立光柱。
- **为什么放在 DAWN**：复用它的镜阵电影、白金色、反亡灵规则；只替换 IMPACT 后的地形结算。
- **服务端**：`SweepJob`（新）——每 tick 在光头位置挖一个半径 2.5 的圆盘 + 记录玻璃化边缘，
  走现有 4000 格/tick 全局预算；不加载无界区块；受保护方块/方块实体策略沿用现有规则。
- **客户端**：光带 + 移动亮头（现有 `beam_strip`/`glow` 贴图），HUD 显示「扫掠方向 / 长度 / 进度」；
  相机从轨道跟拍整条线，不切回地面。
- **参数**：长度、宽度、深度、扫速、是否留玻璃（终端滑条里只暴露长度/宽度，深度/扫速走配置）。

### 2.2 STORM · 星座 CONSTELLATION（参考：Seven Stars 的七节点 + 连线 + 星核）

- **参考做法**：北斗七星投影、七颗流星、连线烧成沟、星核可拾取。
- **我们的原创**：不是北斗，是**原创“末日星座”**（7 个节点的相对坐标写进 XML，形似破碎的
  十字/残月，不是任何现实星座）：
  - MARK 阶段先在地面画出 7 个节点 + 6 条连线预告；
  - 七枚巢荚改为**七颗陨星**按 8–12t 间隔落下（不再刷僵尸）；
  - 全部落地后，6 条连线**逐条点燃**（每条 6t，沿线的沟 3 宽 × 6 深，谷底燃烧）；
  - 每个节点留一颗**星核方块**（可挖，掉「星屑」）；
  - 终曲：整条星座线爆闪一次，连线沟变成发光余烬 20s。
- **和现有 SWARM 的关系**：SWARM 是“生物战/刷怪”，CONSTELLATION 是“地形图案/采集”，
  同一 mode（STORM）的两个 variant，玩家在终端里选。
- **服务端**：`ConstellationJob` —— 7 个 BoxJob（小坑）+ 6 个 LineJob（浅沟），共用预算，
  按节点顺序交错推进；星核方块只在命中点上方一格生成，遇保护/占用则跳过并记录。
- **客户端**：节点环/连线预览 + 逐条点燃的移动亮头（现有 line 渲染）；星核用发光立方体。
- **参数**：图案尺寸 64–1440、坑半径、线宽/深、节点数（默认 7，可 5–9）、是否留星核。

### 2.3 PLANET · 天球仪 ORRERY（参考：Orrery 的多行星/环状抛射）

- **参考做法**：天球仪展开、行星逐颗脱离、主撞 + 环形二次陨石。
- **我们的原创**：主陨石之后，**6 颗副陨石沿一个椭圆环依次落下**（间隔 6t）：
  - 天空用程序化轨道环 + 一个小型“天球仪”缓慢旋转（line/quad，不用新贴图）；
  - 副陨石复用 `carrier_asteroid_cutout` 缩小 + 火尾粒子，落点半径 = 主坑半径 × 1.6；
  - 每个副坑小（半径 3–6），沿环留下熔融带；主坑中心留「行星核」方块（可挖，掉星核碎片）；
  - 所有撞击声音按距离延迟（复用现有雷声队列）。
- **和 BLACK RAIN 的关系**：BLACK RAIN 是“毒雨/环境灾”，ORRERY 是“多体撞击/环状地貌”，
  同一 mode（PLANET）的两个 variant。
- **服务端**：`RingJob` —— 主坑复用现有 BoxJob/PLANET 路径；6 个副坑各一个小编号 BoxJob，
  按顺序排队，全局预算不变。
- **客户端**：天空轨道环（3 圈椭圆）+ 6 颗副陨石依次出现/落下；HUD 显示「副星 3/6」。

## 3. 残骸回收：让战场留下可挖的东西

| 来源 | 方块 | 掉落 | 用途 |
|---|---|---|---|
| FAULT 断层 | `fault_needle` 钉体残骸（3 格高柱） | 钨碎片 ×2–4 | 合成协议核心 / 终端加固件 |
| STORM·星座 | `star_core` 星核 | 星屑 ×2–3 | 合成协议核心 / 快速充能替代品 |
| PLANET·天球仪 | `planet_core` 行星核 | 星核碎片 ×3–5 | 合成协议核心 / 黑雨核心 |

- 全部是可放置、可挖的普通方块（pickaxe 可挖，netherite 更快），**只在地形结算的落点生成**，
  生成前检查空气/可替换、保护名单、方块实体；生成失败只记日志，不阻断打击。
- 配方调整（不削旧路径）：现有六枚协议核心配方保留，但可**用残骸替代部分下界材料**
  （例如焚城核心 = 下界合金碎片 + 烈焰粉×2 + 岩浆膏，或 钨碎片×2 + 烈焰粉×2 + 岩浆膏）。
- 新贴图 3 张（16×16，程序化，走 `tools/relic_art.py`，dHash 门禁不适用但与参考包无关）。
- 配置 `[orbital_strike] leave_relics = true`；关掉 = 纯视觉，不生成方块。

## 4. UX：技能轮盘 + 危险确认 + 冷却环

### 4.1 技能轮盘（参考包 radial menu 的结构，外观用我们自己的末日风）

- 手持遥控器、**按住 `V`**（可配置）打开径向轮盘：六个协议节点 + 当前 variant 名，
  显示锁定/充能/冷却；鼠标指向节点高亮，松开选中（若在终端附近则同步写回终端）。
- 复用 `AmmoWheel` 的按住/松开交互骨架与 `DoomButton` 的配色；纯 `GuiGraphics.fill/drawString`，
  不新增贴图依赖。
- 轮盘打开时游戏不暂停（与终端 GUI 一致），ESC 关闭。

### 4.2 危险尺寸确认（参考包“危险尺寸警告”）

- 终端半径滑条超过 `danger_confirm_radius`（默认 40）时：授权打击前弹出自绘确认页，
  显示「半径 N / 预估方块数 / 可能卡顿或刷怪失控」，确认后才发 `TerminalStrikeAction`。
- 冷却环：轮盘与终端 GUI 的协议节点外圈画充能进度环（0→1），满环时呼吸高亮。

### 4.3 相位字幕（原创文案）

- 每个协议 3–5 条**我们自己写的**战术字幕（例：`CINDER // 弹体分离`、`FAULT // 岩层失稳`），
  在相位切换时短暂出现（现有 HUD 顶部）；文案全部原创，不抄参考包的 16 段无线电台词。
- 配置 `[orbital_strike] phase_subtitles = true`。

## 6. 技术落点

### 6.1 新增/修改文件

**服务端**
- `orbital/engine/StrikeVariant.java`、`StrikeVariants.java`（解析 `<variants>`，内置回落）
- `StrikeProtocol`：增加 `List<StrikeVariant>` / `variant(String)`
- `OrbitalStrikeManager`：
  - `schedule(..., variantId)`；`ActiveStrike.variantId`
  - 新 Job：`SweepJob`、`ConstellationJob`、`RingJob`（与现有 `DestroyJob` 同预算池）
  - 残骸生成：`placeRelic(level, pos, relic)`（保护/占用检查）
- `block/StrikeRelicBlock`（3 种方块复用同一个类 + 枚举）、`registry/ModBlocks` + loot/recipe
- `network/TerminalActionPacket` 新 opcode `VARIANT`；`OrbitalStrikePacket` 加 `variant`

**客户端**
- `OrbitalStrikeClientState.variant`；`OrbitalStrikePacket` 读取
- `client/gui/StrikeWheelScreen`（新，按住 V；复用 AmmoWheel 逻辑）
- `client/renderer/OrbitalScreenFX`：变体 HUD、相位字幕、冷却环
- `OrbitalCarrierPlates`：DAWN·子午线/PLANET·天球仪的局部叠加（光带、副星）
- `SkyfallTerminalScreen`：变体切换行 + 危险确认

### 6.2 网络与兼容

- `NetworkHandler.PROTOCOL` `"2" → "3"`；旧客户端拒绝连接（与 4.0.0 一样要求同版本）。
- 旧存档：终端没有 `Variant.*` → 默认 variant；没有星核/残骸方块 → 不生成任何东西。
- 旧资源包：没有 `<variants>` → 每个协议只有默认变体，行为与 4.0.0 完全一致。

### 6.3 性能预算

- 扫掠：`SweepJob` 每 tick 只挖光头附近一个圆盘（≤ ~200 格），远低于 4000 全局预算；
  整条 256 长沟槽 ≈ 2.5s 扫完 + 几秒余波。
- 星座：7 坑 + 6 沟，全部走现有预算池，按节点/线顺序交错；星核是 7 个方块，可忽略。
- 天球仪：6 个副坑各 ≤ 半径 6，主坑复用现有逻辑；副陨石只是粒子/贴图，不是实体。
- 全部新内容都受 `strike_block_budget`、`max_concurrent_strikes` 管辖。

## 9. 合规与边界

- 参考包**只用于确认机制与节奏**：不复制代码/类名/贴图/音效/字体/文案。
- 新方块、新掉落、新字幕、新图案坐标全部原创；新增贴图走程序化生成 + 门禁。
- 渲染仍只用原版 `RenderType` + 事件相机；不做 shader/FBO/Mixin。
- 世界改动继续走预算 Job、保护名单、chunk ticket、并发上限；不新增无界范围操作。
- 每个阶段独立版本号 + `check_skyfall.py` 扩展判据（variant XML、残骸方块/掉落、轮盘类）。
