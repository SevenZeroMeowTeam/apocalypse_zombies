# 05 · 武器制作流程（六步流水线）

> 每步都**等确认再往下走**。跳步的代价通常不是报错，而是"游戏里看起来不对但门禁全绿"。

## 步骤 0 · 参考图判读

| 做什么 | 工具/产物 |
|---|---|
| 收集真实枪械三视图/剖面图，量比例（全长、枪管长、弹匣位置、枪托长、握把角度） | 参考图放 `art/<武器>/`；判读结论写进 `art/<武器>/README.md` |
| 对标基准是 **TaCZ**：持枪位、换弹/拉栓动作参考其 `ai_awp` 姿态 | [`art/awm/tacz_ai_awp_reference.md`](../../art/awm/tacz_ai_awp_reference.md) |
| 需要按参考图量尺寸 | `python tools/ref_profile_measure.py` |

**铁律**：16 u = 1 方块；枪口 −Z、上 +Y、+X = 射手右侧；原点 = 机匣中心。

## 步骤 1 · 程序化生成几何 + 贴图

```bash
python tools/<武器>_v2.py          # 或 Blockbench JS 生成器：tools/<武器>_bb_gen.js
```

| 要求 | 说明 |
|---|---|
| 圆/管/弧一律用 `boxlib` 图元 | `ring` / `arc_boxes` / `sphere_slabs` / `bolt` / `vents` / `cross_boxes`；**枪管必须是圆形** |
| 贴图 512×512，逐面 UV | 密度 11~13 px/u（Uzi 实测 13，占图集 271/512） |
| 骨骼静态零旋转 | 硬上限：**40 骨骼 / 600 方块** |
| 生成器末尾自带自检 | 跑完看末尾打印，不看等于没跑 |

产出：`assets/apocalypse_zombies/geo/<武器>.geo.json`、`textures/item/<武器>.png`（需要时另有 glowmask）。

## 步骤 2 · 动画（**顺序不能换**）

```
几何生成 → geo 导出 → 动画生成（reset + create_animation + 逐个去 "animation." 前缀 + 设插值 + 导出）
```

- **重跑几何会重掷骨骼 UUID** → 动画必须跟着重建；重建前**先删同名 clip**，否则重复堆叠。
- 关键帧数据写在 `tools/<武器>_anim*.py` 里（可用 `pos()` / `rot()` 做镜像转换，**源码按文件空间书写**）。
- 交付前用 `python tools/<武器>_anim_appshot.py` 抓**整窗**看实时变形 —— MCP 的 `capture_screenshot`
  渲的是**未变形的静态几何**（不同时间点抓出来字节相同），只看它会得出"动画没生效"的错误结论。

- **位移只走该走的轴**：装填/压弹类小件（压入的那一发、漏夹）不许带前后（`z`）分量 —— 观感会变成「沿枪身横滑」。
  用户用**轴色**描述时说的就是这个（绿色 = Y 竖直、蓝色 = Z 前后）。改法见 `tools/reload_press_vertical.py`；
  改完记得同步生成器 JS（`<武器>_bb_anim.js`）并 `node --check` 确认它还能解析，否则下次重导出会把毛病带回来。

产出：`assets/apocalypse_zombies/animations/<武器>.animation.json`。

## 步骤 3 · 门禁（判据 = 退出码）

```bash
for s in tools/check_*.py; do python "$s" || echo "FAIL $s"; done
```

有专门门禁的武器：Uzi（`check_uzi_art` / `check_uzi_anim`）、莫辛（`check_mosin_art` / `check_mosin_anim`）、
AWM（`check_awm_anim`）、弩（`check_crossbow_anim`）、M1（`check_m1_reload`），以及资源接线 `check_gun_resources.py`。

**写新门禁**：把"看起来没问题"变成可执行的不变量（结尾必须回静止姿态、弹匣最低点必须低于握把底、
自由枪机只许沿 +Z 平移…… 见 `art/uzi/DELIVERY.md` 的"关键不变量"一节）。

## 步骤 4 · 量算姿态（**不许眼估**）

```bash
python tools/pose_measure.py
```

- `GunPose.HIP_DX/DY/DZ`（手持落点）与 `<枪>Item.ADS_X/ADS_Y`（开镜抬枪位移）**必须从模型量出来**。
- 实测参考：Uzi `ADS_X = −0.4746`、`ADS_Y = +0.3015`（回写 Java 后残差 0）。
- **基准位一动就必须重解**；`check_gun_resources.py` 会把模型 `display` 与本层数值交叉核对。
- ⚠ 量算脚本里的锚点是**硬编码**的（`rear` / `front` / `anchor_checks`）：改几何**不会报错，只会静默算旧值**。

## 步骤 5 · Java 同步

| 改什么 | 落在哪 |
|---|---|
| 物品行为 | `item/<武器>Item.java`（实现 `GunItem`：`hasScopeOverlay()` / `sightStyle()` / `hidesModelWhileAimed()` / `adsPitch()` / `ADS_X` / `ADS_Y`） |
| 模型与动画键名 | `client/model/<武器>GeoModel.java`（`setCustomAnimations`、`ANIM_*` 常量）与资源路径 |
| 渲染 | `client/renderer/<武器>ItemRenderer.java` |
| 物品模型 `display` 块 | `assets/.../models/item/<武器>.json` |
| 注册 | `registry/ModItems.java`（新物品）；第三人称手臂见 `client/weapon/WeaponArms.java` |

**姿态层不要往骨骼上放位移**：骨骼上的位移会被动画 clip 自己的 `move` 关键帧覆盖（换弹时枪和手会一起沉）。
第一人称"枪摆在哪"只有 `GunPose` 一处真相。

## 步骤 6 · 部署与游戏内取证

```bash
./gradlew --stop
python tools/_deploy_140.py        # 自升版号 + 构建 + 三向对账 + 探锁部署
```

- **完全退出游戏**再重开（无热重载）；**先删 `mods/` 里的旧 jar**。
- 取证：`python tools/game_shot.py --title Minecraft --gain 1.8`（夜晚可用 `--crop` 取局部放大）。

## 步骤 7 · 台账与文档

| 必更新 | 内容 |
|---|---|
| `art/<功能>/DELIVERY.md` | 资产清单、几何/贴图/动画实测数字、**真源脚本**、门禁结果、不变量、踩坑、镜像契约 |

## 一把新枪的检查清单

- [ ] 参考图判读完成，比例换算写在 `art/<武器>/README.md`
- [ ] 几何：圆件用 `boxlib` 图元，枪管是圆、骨骼静态零旋转、≤ 40 骨骼 / 600 方块
- [ ] 贴图：512×512、逐面 UV、密度 11~13 px/u
- [ ] 动画：**在几何之后**生成、clip 名无 `animation.` 前缀、结尾回静止姿态、符号与参考枪一致
- [ ] 门禁：13 个 `check_*.py` 全 `exit 0`
- [ ] 姿态：`pose_measure.py` 量出 `HIP_*` / `ADS_X` / `ADS_Y` 并回写 Java
- [ ] Java：`GunItem` 契约实现正确（铁瞄 → `hasScopeOverlay()=false`）
- [ ] 部署后游戏内实机验证（含第三人称、换弹、开镜）
- [ ] 台账 `DELIVERY.md` + `readme.md` 更新日志
