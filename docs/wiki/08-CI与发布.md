# 08 · CI 与 GitHub 发布

仓库：`SevenZeroMeowTeam/apocalypse_zombies`（SSH 推送）。工作流：`.github/workflows/build.yml`（`build`）。

## 两条发布轨

| 轨 | 触发 | tag | 附件 | 说明 |
|---|---|---|---|---|
| **预览版** | 任何 `push`（任意分支） | `preview`（单个预发布，**每次提交原地刷新**） | 开发包 + `-clean` 包 | 固定下载地址；正文写明"开发包含临时借用的 TaCZ 音效，**仅供本地预览/自用**" |
| **正式版** | `push` 到 `main` | `v<mod_version>` | 只挂 `-clean` 包 | 同一版本的后续提交 = **覆盖附件 + 刷新说明**，不重复建 Release |

固定地址：
- 预览版 `https://github.com/SevenZeroMeowTeam/apocalypse_zombies/releases/tag/preview`
- 正式版 `https://github.com/SevenZeroMeowTeam/apocalypse_zombies/releases/tag/v<版本>`

## 工作流步骤

| 步 | 作用 |
|---|---|
| `actions/checkout@v5` | 拉代码 |
| `actions/setup-java@v5`（temurin 17） | **下载 runner 上的 JDK 17**（设好 `JAVA_HOME`） |
| `gradle/actions/setup-gradle@v5` | Gradle 缓存 + wrapper 校验 |
| `chmod +x gradlew` | 仓库来自 Windows 开发机，checkout 可能丢可执行位 |
| Read mod version | 从 `gradle.properties` 取 `mod_version` 写进 `$GITHUB_OUTPUT` |
| Build | `set -o pipefail` + `./gradlew build cleanJar --no-daemon --stacktrace 2>&1 \| tee build.log` |
| Report failure tail（`if: failure()`） | 把 `build.log` 末 45 行打成 **check-run annotation** —— 见下节 |
| Upload build log（`if: failure()`） | 失败日志留档 artifact |
| Upload jars | 两个 jar 留档 |
| Publish preview / official | 用 `GH_TOKEN` + `gh release` 建/更新 Release |

`permissions: contents: write` 是建 Release 的硬前提；`concurrency` 按分支排队（避免两个 run 抢同一个 Release）。

## 四个 action 都跑在 node24

| action | 版本 | `runs.using` |
|---|---|---|
| `actions/checkout` | v5 | node24 |

## 仓库自己解决 Java（不依赖任何机器配置）

```groovy
// settings.gradle
plugins {
    id 'org.gradle.toolchains.foojay-resolver-convention' version '0.8.0'
}
```

```properties
# gradle.properties
org.gradle.java.installations.auto-download=true
```

解析顺序：`JAVA_HOME`（CI 由 setup-java 设好）→ 本机已装 JDK → **Foojay 自动下载**（落到 `~/.gradle/jdks/`）。

⚠ **Gradle 8 自己不会下 JDK**：没有上面那个解析器时，`auto-download=true` 是空转，runner 版本对不上就是
`No matching toolchains found`。另外 `auto-download=false` 若留在**用户级** `~/.gradle/gradle.properties`，
会压住仓库里的 `true`。

⚠ **仓库的 `gradle.properties` 绝不能写机器专属绝对路径**：`org.gradle.java.installations.paths=D:\java`
在 Linux runner 上被 Gradle 当 **URI** 解析，配置期直接崩：

```
java.net.URISyntaxException: Illegal character in opaque part at index 2: D:\java
    at ...FileOrUriNotationConverter.convertToUrl
```

而报错栈里**一个 `build.gradle` 的行号都没有**，看起来像"构建环境坏了"。命令行 `-D` **盖不住**
properties 文件里的同名键，别指望用覆盖绕过。

## 匿名怎么读 CI 失败原因（重要）

| 途径 | 可行性 |
|---|---|
| `/actions/runs/<id>/logs` 整包日志 | ❌ 需仓库 admin |
| 网页版日志视图 | ❌ 懒加载，`innerText` 抓不到 |
| **check-run annotations** | ✅ **匿名可读** —— 这就是工作流里那条注解链存在的理由 |

所以失败时必须让 workflow **自己把原因打成注解**（`Report failure tail` 那一步）。删掉它 = 以后 CI 挂了只能看到
一句 `exit code 1`。**这也是拒绝合并"重写工作流"那类 PR 的原因**：改动看着更整洁，但会顺手把这条链删掉。

（演练过的现实案例：GitHub 云端 agent 依据同一次失败开过 PR #1，诊断结论正确，但它的分支基于修复前的 `main`，
合并会把失败日志注解链一起回退 —— 已关闭，不合并。）

## 仓库卫生（跨平台 CI 的前提）

| 项 | 规则 |
|---|---|
| 换行与可执行位 | `.gitattributes` 强制 `gradlew`/`*.sh` 为 **LF 且可执行**（开发机 Windows、runner Linux） |
| `gradle/wrapper/gradle-wrapper.jar` | **必须入库**，CI 靠它启动 Gradle（`.gitignore` 里专门写了提醒） |
| 机器专属配置 | 不进仓库（JDK 路径、代理、本地绝对路径） |
| 不该进仓库的 | `build/`、`.gradle/`、`run/`、`logs/`、`build.log`、美术栅格图/音频、本机会话残留（`hermes-update-fix/`、`JJI54557149985_obj/`、`x/`） |

## 推送后核对（别只看"步骤绿"）

```bash
# 匿名 API 额度 60/小时，用完会被限流；限流时改看网页或等重置
curl -s "https://api.github.com/repos/SevenZeroMeowTeam/apocalypse_zombies/actions/runs?per_page=3"
curl -s "https://api.github.com/repos/SevenZeroMeowTeam/apocalypse_zombies/releases"
```

**把 Release 资产下载回来解包点数**才是硬证据：

- `-clean` 包里 `.ogg` 数必须为 **0**（音效已剥）、`mods.toml` 在、`.class` 与 geo 数对得上
- 与本地 `build/libs/*-clean.jar` **逐条比条目集**
- 注意 clean 包里的手工动画被 `rename` 成正式名（`awm.animation.json`），按 `handmade` 找会说"没进包"（假警报）

## CI 故障对照

| 症状 | 根因 | 处置 |
|---|---|---|
| 配置期崩 `Illegal character in opaque part ... D:\java` | 仓库里写了 Windows 绝对路径的 JDK 位置 | 挪到用户级 `~/.gradle/gradle.properties` |
| `No matching toolchains found` | 缺 foojay 解析器，或 `auto-download` 被压成 false | 见上节 |
| `./gradlew: Permission denied` | checkout 丢了可执行位 | 保留 `chmod +x gradlew`，并让 `.gitattributes` 标 `*.sh`/`gradlew` |
| 只有 `exit code 1`，看不到原因 | 失败日志注解链被删或在 Gradle 启动前就失败 | 恢复 `tee build.log` + `Report failure tail`；用 `actions/upload-artifact` 留档 |
| Release 每次新增一条 | 用了 `gh release create` 而没先判断存在 | 先 `gh release view <tag>`，存在就 `upload --clobber` + `edit` |
