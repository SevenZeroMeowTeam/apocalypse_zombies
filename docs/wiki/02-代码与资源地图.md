## 三条要记住的契约

1. **`GunItem` 接口 = 枪械行为契约**（`src/main/java/.../item/GunItem.java`）
   - `hasScopeOverlay()`：**是否画瞄具遮罩**（"准星是不是这个瞄具画的"）
   - `sightStyle()` → `SightStyle.TELESCOPE / ...`：遮罩画成哪一种（只在 `hasScopeOverlay()==true` 时读；默认 `TELESCOPE`）
   - `hidesModelWhileAimed()`：开镜时是否把手中模型藏掉（**与上面两个刻意分开**）
   - `adsPitch()`：模型 `display` 的俯仰，姿态层要用它做共轭抵消
   - **`ammoTypes()` / `currentAmmo()` / `selectAmmo()`（1.1.52 起）= 弹种契约**。默认实现就够用
     （`STANDARD` + `THERMITE` + `EXPLOSIVE`，读写 stack 的 `Shell` 键），只有霰弹枪重写
     `ammoTypes()` 补一个独头弹。**效果不在枪里**，而在 `event/AmmoEffects` 那一处
     `LivingHurtEvent` 上 —— 所以"给所有枪加一种新弹"是零逐枪改动的
   - 例：Uzi 是**铁瞄** → `hasScopeOverlay()=false`、`hidesModelWhileAimed()=false`
2. **`GunPose` = 第一人称"枪摆在哪"的唯一真相**（`client/weapon/GunPose.java`）
   - `HIP_DX/DY/DZ`（持枪落点）、`SPRINT_*`（跑步姿态）、`ADS[8]`、`MODEL_FOV_AIM/HIP`
   - 为什么不在骨骼上做：**骨骼上的位移会被动画 clip 自己的 `move` 关键帧覆盖**（换弹时枪和手会一起沉下去）
   - 它乘的是一整套链：相机变换 · 本层 · 物品 `display` · `ItemRenderer` · 模型像素/16
   - 改这里必须重跑 `tools/pose_measure.py`（`check_gun_resources.py` 会交叉核对模型 `display` 与本层数值）
3. **几何 ↔ Java ↔ 动画三向绑死**
   - 重跑几何 → 骨骼 UUID 重掷 → **动画必须重建**（顺序只能是：几何 → geo 导出 → 动画生成）
   - 姿态常量（`HIP_*`、`ADS_X/ADS_Y`）必须是**量出来的**，且**基准位一动就要重解**

## 数据流（枪械开火，粗线）

```
左键 → ClientEvents/KeyBindings → FirePacket ─┐
                                              ├─→ 服务端权威判定（弹药 / NBT 状态机 / 冷却）
按住 R 弹轮盘 → AmmoWheel → ReloadPacket ─────┘        │   （ReloadPacket 带上轮盘选中的 AmmoType）
                                                       ├─→ 生成 BulletProjectile（用 GunFrame 的枪口点）
                                                       └─→ 命中 → hurt() → LivingHurtEvent
                                                              └─→ AmmoEffects：铝热弹点燃 / 爆炸弹炸开
客户端表现（第一人称 GunPose + 第三人称 WeaponArms）←── 广播表现封包
```
