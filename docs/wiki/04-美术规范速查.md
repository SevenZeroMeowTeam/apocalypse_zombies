## 铁律（违反即返工）

| 项 | 规则 |
|---|---|
| 单位 | **16 u = 1 方块 = 1 m**；**1 u = 6.25 cm**；成品枪长 **1.0 ~ 1.5 格** |
| 坐标 | **枪口 = −Z**、**上 = +Y**、**+X = 射手右侧**；原点 = **机匣中心**（握把在下方） |
| 骨骼 | **一根都不许带旋转**（静态姿态零旋转） |
| 圆/管/弧 | 程序化路径用 **`boxlib` 图元**（`ring` / `arc_boxes` / `sphere_slabs` / `bolt` / `vents` / `cross_boxes`）；手工路径用 Generate Shape。**禁止手堆方块拼圆** |
| 贴图 | 每枪一张 **512×512** PNG，透明背景；**逐面 UV 图集**，密度 **11 ~ 13 px/单位** |
| 动画 | **必须骨骼驱动**（Translation / Rotation）；**禁止整模型缩放**伪装动画 |
| 面数 | 方块件为主；圆柱分段 **8 ~ 12 边** |
| 锚点 | 枪口 / 抛壳点 / 镜光轴等关键锚点，**改一处要两处一起改**（生成器注释**不保证**与 Java 同步） |

## 与本项目实际做法的差异（通用提示词 vs 落地）

| 通用说法 | 本项目实际 |
|---|---|
| 在 Blockbench 里手工建模 | **程序化生成是主路径**（生成器脚本 → geo + 逐面 UV + 贴图），Blockbench 只用来**看和微调** |
| 必须用 Generate Shape 插件 | 等价物是 **`boxlib` 图元**；插件仅在手工微调时用 |
| 动画写在 `.animation.json` 里 | 姿态主要由 **Java 程序化驱动**（`*GeoModel.setCustomAnimations` + `GunPose`）；动画文件里多为通道数据 |
| 交付给一份建模说明 | 交付 = 生成器改动 + geo/贴图/glowmask + **门禁全绿** + **姿态常量已量算同步** + `readme.md`/台账更新 |

## 两条最贵的坑（来自 `art/uzi/DELIVERY.md`）

1. **导出的镜像契约**：导出时所有带 pivot 的元素 **x 取反**；并且**动画通道也镜像**，但 position 与 rotation 规则不同：

   | 通道 | 作者空间 → 文件空间 |
   |---|---|
   | `position` | **x 取反**，y / z 不变 |
   | `rotation` | **x 与 y 取反**，z 不变 |

   参考枪的 `.animation.json` 是**文件空间**；把它的数值原样抄进 Blockbench 的**作者空间**，
   整段动作会上下/左右翻过来，而**文件、门禁、导出日志全都正常**。统一用脚本里的 `pos()` / `rot()` 转换，
   **源码一律按文件空间书写**。
2. **clip 名对不上 = 静默不播**：`create_animation` 会把名字存成 `animation.<name>`，而 Java 按 `"static_idle"` 取键；
   导出文件看起来完全正常，游戏里就是不播。导出前逐个改名去前缀。

其他同源坑（UUID 重掷、`lerp_mode`、`risky_eval` 载荷限制、MCP 截图渲的是**未变形**静态几何等）见
`art/<功能>/DELIVERY.md` 的"踩到的坑"一节 —— **每个功能都攒了一份，接手前先读完那一节。**
