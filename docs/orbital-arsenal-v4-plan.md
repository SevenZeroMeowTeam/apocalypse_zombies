# 《天陨武库》v4 计划表

> 定位：**the-shooting-star-decompiled.zip 只作「结构 / 电影语言 / 地形签名 / UX 节奏」的参考，
> 代码、贴图、音效、字体、技能内容一律不取。**
> 你给的 8 张图（卫星 / 天基炮 / 天基矛发射器 / 宇宙 / 小地球 / 小行星 / 引力奇点 / 等离子发射器）
> 从本轮起**只作设计参考**，不进 jar；包内先用占位资产跑通，再换成项目自绘。
>
> 现状基线：`3.8.0`（引擎 v2 + 六份原创末日协议已落地）。
> 本计划是 **3.8.0 之后的一版（4.0.0）**，不是从零开始。

## 0. 先核对现状：哪些已经做了，别重复建

| 能力 | 参考包 | 我们（3.8.0） | 本轮差距 |
|---|---|---|---|
| 六种打击、各自独立幻想 | 6 技能（正式版） | 六协议：焚城/断层/隔离/蜂群/黎明/黑雨 | 无 |
| 相位状态机 + 数据化时间表 | `star/*.java` 硬编码 + FX cue | `StrikeProtocol` + `strike/*.xml` 六份 | 无 |
| 服务端真实改地形 | 自研多线程世界编辑引擎（60KB） | 预算式 Job + chunk ticket + 保护规则 | 无（刻意不采用线程池） |
| 相机电影 | Mixin 劫持 Camera + 关键帧导演 | Forge `ComputeCameraAngles` + `OrbitalCinematic` | 无（不引 Mixin） |
| HUD / skip / 倒计时 | 有 | 有（`K` 跳过，六协议 HUD） | 见 C 线 |
| 载体视觉 | 全屏 raymarching GLSL | 2.5D 电影板 + 程序化卫星/行星/星云 | **A 线：资产非原创** |
| 技能菜单 / 滑条 / 键位 | 技能轮盘 + 半径/威力/伤害/速度滑条 | **没有**（潜行右键切协议 + 配置文件） | **B 线：最大缺口** |
| 过场对附近玩家播放 | 有 | 没有（只发给施放者） | C 线 |
| 解锁 / 进度 / 重击警告 | 有（关注数解锁） | 没有 | B 线 |
| 相位断线/卡顿对齐 | 无（纯本地电影） | 只有开始包，客户端本地推相位 | C 线 |

结论：**引擎和内容骨架已经成立，缺的是「运营层 + 演出层 + 原创资产」。**
所以 v4 不重写引擎，做三件事：**终端化（B）→ 补完同步与多人（C）→ 资产原创化（A）**。

## 1. 一句话体验

> 玩家不再「掏出一个遥控器就炸地图」，而是**建造一座天陨指挥终端、装填协议核心、等它充能，
> 然后在六边形轮盘上选中一份末日预案、调半径/威力/速度、授权从天而降的一击**，
> 附近的人一起看着那道属于自己模组的电影板与光束落下来。

## 2. B 线：天陨指挥终端（玩法闭环）

### 2.1 核心循环

```
挖矿/搜集 → 合成「天陨指挥终端」→ 放下 → 放入「协议核心」
   → 终端解锁该协议 → 终端充能（冷却）→ 打开 GUI 选协议/调参数
   → 授权打击 → 电影 + 命中 + 余波 → 冷却 → 下一发
```

### 2.2 新增内容清单

| 类型 | ID / 类 | 说明 |
|---|---|---|
| 方块 | `skyfall_terminal` | 1 格主机，`BlockEntity` 存解锁位图/冷却/参数；会发光、有工作粒子 |
| 方块 | `skyfall_antenna` | 可选装饰柱（3 格），给终端加充能速度；不做也能跑通 P1 |
| 物品 | `protocol_core_<id>` ×6 | 六个协议核心（`cinder/fault/quarantine/swarm/dawn/black_rain`），右键终端安装 |
| 物品 | `skyfall_key`（可选） | 便携调用器：替代现在的 `orbital_strike_remote`，只调用已解锁协议 |
| 菜单 | `SkyfallTerminalMenu` + `SkyfallTerminalScreen` | 六边形轮盘 + 参数面板 + 授权按钮 |
| 注册 | `ModBlocks`（新建）、`ModBlockEntities`（新建） | 项目目前**没有**自定义方块注册类，要新开 |

### 2.3 终端 GUI 布局（原创，不照抄参考包的菜单）

```
┌──────────────────────────────────────────────────────────┐
│  SKYFALL TERMINAL // 天陨指挥终端          [X]            │
│                                                          │
│            ◇ 焚城        ◇ 断层        ◇ 隔离            │
│                 ╲         │         ╱                    │
│              ◇ 黑雨 ── ◎ ── ◇ 蜂群      ← 六边形 6 节点  │
│                 ╱         │         ╲                    │
│            ◇ 黎明        （中环：当前协议大图标）          │
│                                                          │
│  ┌──────────── 参数 ────────────┐  ┌──── 状态 ────────┐  │
│  │ 半径   ▁▂▃▄▅▆▇ 24           │  │ 充能 ████░░ 64%  │  │
│  │ 威力   ▁▂▃▄▅▆▇ 100%         │  │ 冷却 12s         │  │
│  │ 速度   ▁▂▃▄▅▆▇ 1.0×         │  │ 核心 ● 已安装     │  │
│  │ 过场   [开]  附近播放 [开]   │  │ 上次 03:12       │  │
│  └──────────────────────────────┘  └──────────────────┘  │
│         [ 授权打击 ]      ⚠ 半径 > 40 会明显卡顿          │
└──────────────────────────────────────────────────────────┘
```

- 未安装核心的节点显示为**暗色锁**，悬停提示「需要：焚城协议核心」；
- 参数直接写进 `BlockEntity`（不是全局配置），不同终端可以不同；
- 危险阈值触发二次确认（`Are you sure` 风格自绘弹窗，不用原版 ConfirmScreen）；
- 所有外观沿用现有 `DoomButton` / `DoomMenuTheme` 的末日风，不引入新 UI 框架。

### 2.4 数据模型（`SkyfallTerminalBlockEntity`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `unlocked` | `int` 位图（6 位） | 已安装的协议核心 |
| `selected` | `String protocolId` | 当前选中协议 |
| `cooldownEnd` | `long gameTime` | 充能结束时刻 |
| `radiusMul` | `float 0.5~2.0` | 终端级半径倍率（叠在协议倍率上） |
| `powerMul` | `float 0.5~2.0` | 伤害倍率 |
| `speedMul` | `float 0.3~3.0` | 电影 + 相位速度倍率 |
| `filmOn` | `boolean` | 本终端是否播过场 |
| `broadcast` | `boolean` | 过场是否发给附近玩家 |
| `owner` | `UUID` + `name` | 放置者；权限见 2.6 |

- NBT 序列化，随区块保存；**旧存档没有终端 → 不迁移任何东西**；
- 现有 `orbital_strike_remote` 保留可用（老存档不炸），但新玩家引导走终端。

### 2.5 充能规则（先简单，不做能量网）

| 规则 | 默认值 | 配置键 |
|---|---|---|
| 终端基础充能时间 | 90s | `terminal_charge_seconds` |
| 每装一个协议核心 +充能 | +0s（只解锁，不加时间） | — |
| 每次打击消耗 | 清空充能 | — |
| 天线加成 | 每格 -15% 充能时间（最多 3 格） | `antenna_speedup` |
| 打击后冷却（协议差异） | 沿用 `OrbitalStrikeMode.cooldownSeconds` | 现有 `cooldown` |

> **决策点**：要不要引入「能量单位/燃料消耗品」？默认**不要**——先跑通冷却循环，避免变成另一个要平衡的经济系统。

### 2.6 多人 / 权限

- 终端有 owner；`terminal_access` 配置：`owner` / `owner+team` / `anyone`（默认 owner）；
- 冷却按**终端**算，不按玩家算（防止多人轮着放）；
- 打击仍然只由服务端授权：GUI 的「授权打击」发一个 C2S 包（协议 id + 终端 pos），
  服务端校验距离/权限/冷却/维度/解锁位后再走 `OrbitalStrikeManager.schedule`；
- **绝不相信客户端传来的半径/伤害**：参数以服务端 BlockEntity 为准。

## 3. C 线：演出与同步补完

| 项 | 现状 | v4 做法 | 验收 |
|---|---|---|---|
| 相位同步 | 只发开始包，客户端按 XML 本地推 | 新增 `StrikePhasePacket`：每个相位切换发一次（协议 id / 相位 / 服务端 tick） | 卡顿 2s 后客户端相位仍与服务端一致 |
| 过场广播 | 只发施放者 | 服务端按 `broadcast` 向半径内玩家发包；每个客户端可本地关闭 | 第三人称能完整看到电影；关闭者只看到世界效果 |
| 中断/取消 | 关服清理已有 | 终端被拆/区块卸载/玩家死亡 → 服务端取消未结算阶段并回滚挂起状态 | 任意时刻打断，无残留任务、无二段伤害 |
| 性能 | 4000 格/tick 预算 | 增加 `strike_block_budget` 配置；大半径分帧提示 | 默认尺寸 TPS ≥ 18 |
| HUD | 代号/相位/倒计时/K | 增加六边形节点进度、危险区距离提示、附近玩家「被广播」标记 | 不遮挡准星与血条 |
| 音效 | 分阶段 cue 已有 | 补「终端充能」「协议安装」「授权确认」三组音 | 全流程有声音反馈 |

约束不变：**只用原版 `RenderType` + 事件相机，不引 shader / FBO / Mixin**（Embeddium 兼容）。

### 4.2 做法（推荐：分层 2.5D 自绘板）

每张板 4 层，`tools/orbital_art.py` 生成 + 手工修：

1. **背景层**：程序化星野 + 行星弧（噪声/分形，不采样参考图像素）；
2. **载体层**：用参考图只取**构图语言**（机位、轮廓方向、明暗分区、主色），重新画结构线；
3. **发光层**：炮口/反应堆/环流，独立贴图给 `entityTranslucentEmissive` 用；
4. **前景层**：遮挡/尘埃/光斑，让镜头推近时有层次。

验收：
- 参考图与成品做**感知哈希/SSIM 对比**，只允许「同类构图」，不允许像素级相似；
- jar 内不再含参考图字节；参考图移到 `art/reference/` 并写 `README`（仅参考，不随包）；
- `NOTICE.md` / `readme.md` 许可段同步更新；
- 卫星、地球、星云继续保留程序化几何（`OrbitalSpaceStage`）作为低画质/无贴图回落。

> 备选方案：不画板，直接把五种载体做成**程序化 3D 舞台**（像现在的卫星/行星那样）。
> 更原创、包体更小，但电影质感会明显下降（照片板 → 几何体）。默认选自绘板，见 §7 决策 1。

## 8. 风险与边界

1. **资产工时最大**：6 张 1408×768 + 5 张小图，画不好不如不画 → 先 A1 小图验证风格，再决定是否继续；
2. **自定义方块是项目首次**：`ModBlocks`/`BlockEntity`/`BlockEntityRenderer`/loot/model 一次要齐全，容易漏资源导致紫黑块；
3. **联机权限**：默认 owner-only 可能让专服玩家不适，配置要有 `anyone` 逃生门；
4. **性能**：终端 GUI 只是界面，不额外 tick；打击仍走既有预算 Job；
5. **兼容**：不引 shader/FBO/Mixin；旧 `orbital_strike_remote` 与旧存档保持可用；
6. **不做**：参考包的 GLSL 后期管线、Mixin 相机、线程池世界编辑、字体与音效素材。

| 项 | 落地 |
|---|---|
| 终端方块 + 方块实体 | `block/SkyfallTerminalBlock`、`SkyfallTerminalBlockEntity`；新注册类 `ModBlocks`、`ModBlockEntities` |
| 六协议核心 | `orbital/terminal/ProtocolCoreItem`；6 个物品；本版只给焚城核心配方 |
| 服务端授权 | `SkyfallTerminalManager.authorize()` → `OrbitalStrikeManager.schedule(...)` 新重载（半径/伤害倍率/下落速度倍率） |
| GUI | `client/gui/SkyfallTerminalScreen`：六边形轮盘 + 三条滑条 + 过场 + 充能条 |
| 网络 | `TerminalSyncPacket`（S2C）、`TerminalActionPacket`（C2S），已注册进 `NetworkHandler` |
| 配置 | `[skyfall_terminal]` 5 项 |
| 资产 | `tools/skyfall_art.py` 程序化生成：方块贴图 + 六核心贴图 + 模型/blockstate |

### 与计划的偏差（有意为之）

1. **射击入口没有换成 GUI 按钮**：仍是「手持遥控器瞄准右键」，终端只负责解锁/调参/充能/授权。
   这样不用新写一套「关界面→进入瞄准模式→确认」的客户端状态机，P2.5 再做。
2. **速度滑条只作用于「下落段」**：`lockTicks` 由协议 XML 相位固定，避免客户端电影与服务端相位脱节；
   面板上标注为「下落速度」。整段电影变速留到 C 线。
3. **威力滑条只作用于走 `damageArea` 的协议**：断层（裂谷）/隔离/黎明的净化伤害走各自独立函数，
   本版不缩放；焚城闭环不受影响。
4. **未做**：相位同步包、过场广播附近玩家、终端额度/燃料、五枚剩余核心的配方、资产原创化 A 线（参考图仍在包里）。

### 验证

- `gradlew build --offline` 通过，产出 `apocalypse_zombies-3.9.0.jar`；
- 专用服务器 `runServer` 启动成功（注册/数据包零错误）；
- RCON 实测：`setblock` 放置终端 → 方块实体 NBT 正确；`loot spawn ... mine` 正常掉落终端物品。
- 未做：客户端实机目检（本环境无法启动图形客户端）、两名玩家联机、完整打击流程实机复放。
